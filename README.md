# Аким на 5 часов

Симулятор решений для условной Астаны: выберите пять мер, распределите бюджет и посмотрите, как меняются районы. Основа интерфейса — дизайн Claude из `claude.front`, сервер расчёта — FastAPI из ветки `codex/akim-engine`. Обе части объединены в этом проекте.

На большом экране видны каталог, схема города с портфелем и результат. Контуры пяти районов взяты из [Astana Scheme](<Astana Scheme/README.md>) на основе упрощённых данных OpenStreetMap. Меру можно перетащить на район или добавить через выпадающий список. На телефоне каталог открывается отдельной панелью. Кнопка «На экран» увеличивает результат для проектора.

## Запуск с настоящим сервером

Для воспроизведения использовались Node.js 24.11 и Python 3.13. Node.js/npm нужны для интерфейса; Python — для сервера. Первый запуск установки зависимостей требует доступа к пакетным реестрам.

**PowerShell, первый терминал, из корня репозитория:**

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

**Bash, первый терминал, из корня репозитория:**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
test -f .env || cp .env.example .env
.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

**Второй терминал, PowerShell или Bash, из корня:**

```text
cd claude.front
npm ci
npm run dev
```

Откройте [интерфейс](http://127.0.0.1:5173). [Проверка сервера](http://127.0.0.1:8000/api/health) должна вернуть `status: "ok"`. Если порт 5173 занят, Vite напечатает фактический адрес; используйте его.

HTTP включён по умолчанию. Браузер обращается к относительному `/api`, а Vite передаёт запросы на `http://127.0.0.1:8000`. Числа приходят с сервера. Никакой отдельный API-адрес в браузере телефона для этого не нужен.

## AI и режим без сервера

`OPENAI_API_KEY`, `AI_MODEL` и `RULESET` задаются только в корневом `.env`. Ключ не нужен для расчёта, оптимизатора и лидерборда. Без ключа или при недоступности модели сервер возвращает объяснение по рассчитанным фактам с пометкой «без AI». Реальные секреты не должны попадать в `claude.front` или переменные `VITE_*`: содержимое последних доступно браузеру.

Отдельное локальное демо открывается по [ссылке с ?demo=1](http://127.0.0.1:5173/?demo=1) или командой `npm run dev:demo`. В нём расчёт выполняется в браузере, анализ составляется по правилам, а рейтинг хранится только на этом устройстве. Черновики live и demo разделены. При обрыве сервера приложение предлагает явно перейти в демо; автоматической подмены серверных результатов нет.

Демо работает без API после загрузки страницы и ресурсов. Установка PWA, service worker и гарантированное открытие сайта без сети с нуля не реализованы.

## Телефон и общий экран

Запустите frontend командой `npm run dev:lan`. Компьютер и телефон должны быть в одной доступной локальной сети. Узнайте IPv4-адрес компьютера через `ipconfig` в Windows и откройте на телефоне `http://<IP-компьютера>:5173` — например, `http://192.168.1.25:5173`. Если Vite выбрал другой порт, подставьте его.

Адрес `127.0.0.1` на телефоне указывает на сам телефон. Backend можно оставить на `127.0.0.1:8000` компьютера: к нему обращается Vite-прокси. При недоступности проверьте выбранную сеть, изоляцию клиентов Wi-Fi и доступ к порту Vite в брандмауэре.

«На экран» — явный режим показа, подходящий для телевизора или проектора. Он не пытается угадать телевизор по разрешению. Фактические устройства и браузеры нужно проверять по [UX-чеклисту](Доки/ux-checklist.md); эмуляция ширины не заменяет проверку Safari или управления пультом.

## Проверки и сборка

В `claude.front`:

```text
npm test
npm run typecheck
npm run build
```

Backend, PowerShell из корня:

```powershell
Push-Location backend
..\.venv\Scripts\python.exe -m pytest tests -q --basetemp=./data/cache/pytest-temp
Pop-Location
```

Backend, Bash из корня:

```bash
cd backend
../.venv/bin/python -m pytest tests -q --basetemp=./data/cache/pytest-temp
cd ..
```

В backend есть проверки эталонных чисел, ограничений, полного перебора, событий, AI fallback и API для карты. Фронтенд проверяет адаптацию реальных ответов сервера, ошибки сети, сохранение черновика и пользовательские сценарии.

Для локальной проверки готовой сборки при запущенном backend: `npm run preview -- --host 127.0.0.1 --port 4173` из `claude.front`. Preview также проксирует `/api`, но служит для проверки сборки.

Для размещения сайта нужны статические файлы `claude.front/dist` и постоянный reverse proxy, который передаёт `/api/*` в FastAPI с сохранением префикса `/api`. Настройки dev/preview-прокси Vite не переносятся в статические файлы.

## Демонстрация за минуту

1. Выберите «Пример организаторов»: M7, M8 и M10 в Нуре, M12 для города, M5 в Сарыарке.
2. При `RULESET=dataset`, без события, ожидаются расход **95**, Score **56.54307**, прирост **+3.98539**, критические показатели **2 → 0**. Интерфейс округляет числа для показа.
3. Сохраните «План А». Удалите M5: карта показывает допустимый черновик, официальный Score и фиксация недоступны. Верните меру перетаскиванием или через список районов; «Отменить» возвращает предыдущее изменение.
4. Откройте Нуру: видны десять показателей до/после. Посмотрите предложенную замену и нажмите «Применить» только если хотите её принять.
5. Зафиксируйте план под именем команды. Сервер сохранит результат и запустит анализ. Откройте «Команды» или скачайте Markdown-отчёт.
6. Включите «На экран» для показа результата жюри.

Полный перебор режима `dataset` содержит **694 395** допустимых планов; максимальный Score — **57.236735**. Процентиль считается по этому перебору сервером. Первое построение кэша занимает заметное время, последующие запросы используют кэш. В локальном демо точный процентиль не показывается. Режим `all_directions` использует другой набор правил и сценарий по пяти направлениям; пример организаторов в нём недопустим.

## Что сохраняется и какие есть ограничения

- Черновик и один «План А» сохраняются в localStorage данного браузера и адреса сайта. Между устройствами они не синхронизируются. После перезагрузки баллы считаются заново; история отмены действует в текущей сессии.
- Повреждённый черновик или смена версии данных/правил объясняются сообщением. Неактуальные ответы на запросы не заменяют результат нового плана.
- Общий лидерборд находится в SQLite backend. Имя команды — ключ записи: повторная отправка под тем же именем обновляет её. Учётные записи и проверка владельца имени не реализованы.
- Событие меняет исходные показатели или бюджет. Такие сценарии можно пересчитать, объяснить и экспортировать, но они не участвуют в общем рейтинге и поиске оптимума.
- Схема пяти районов использует упрощённые контуры из Astana Scheme и условные показатели хакатона. Контуры не заменяют официальные границы, баллы не являются прогнозом развития Астаны. Геоданные: © участники OpenStreetMap, ODbL.
- Drag and drop дополняет кнопки и списки. На сенсорном устройстве можно пройти весь сценарий без перетаскивания.

Подробности интерфейса и API-адаптера: [claude.front/README.md](claude.front/README.md). Порядок ручной проверки: [Доки/ux-checklist.md](Доки/ux-checklist.md).
