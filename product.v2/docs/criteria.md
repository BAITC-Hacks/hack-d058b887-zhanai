# Самооценка по критериям жюри

Для каждого критерия указано, где это можно проверить в репозитории. Пути даны относительно `product.v2/`.

## 1. Соответствие задаче и работоспособность (25)

| Требование | Доказательство |
| --- | --- |
| Одинаковый бюджет и данные для всех | `backend/data/rules.json` (`budget: 100`), `GET /api/catalog`; клиент не может передать стоимость или Score (`schemas.py`, `extra="forbid"` → 422) |
| 5 решений по 5 направлениям | 14 мер в `measures.json` (transport, ecology, social, safety, services); `validator.py`: ровно 5 разных мер, ≤ 2 из направления, режим `all_directions` |
| Нельзя превысить бюджет | `BUDGET_EXCEEDED` в `validator.py`, `result = null`; в UI недоступные по цене меры и «превышен на …» в шапке; тесты `test_rejection`, `test_events_recalculate_budget_and_baseline` |
| Решения влияют на показатели | `simulator.py`: `beforeIndicators / afterIndicators`, `criticalBefore / criticalAfter` по каждому району; карта и панель района |
| AI объясняет результат и компромиссы | `POST /api/explain`: `strengths`, `risks`, `consequences`, `recommendations`, `decisions[]`; упущенные синергии и неохваченные направления в фактах |
| Изменение решений меняет Score | 52.56 (база) → 56.54 (пример) → 57.21 (замена M5 на M3 в Нуре) → 57.24 (оптимум); при секвестре (лимит 90) оптимум 57.19 среди 400 145 планов; `preview` пересчитывает на каждом шаге |
| Все опциональные пункты | лидерборд, визуализация районов, рекомендации + перебор (и во время события), события с изменением бюджета, Markdown-презентация (см. таблицу в `README.md`) |
| Работает без внешних зависимостей | без ключа OpenAI сценарий полностью рабочий, объяснение помечено «без AI»; при сбое AI расчёт не страдает |

## 2. Техническая реализация (25)

- **Разделение ответственности:** валидатор, симулятор, факты, AI, оптимизатор, события, лидерборд и презентация — отдельные модули (`backend/app/`), `main.py` только их связывает. Схема: `docs/architecture.md`.
- **Сервер — источник истины;** `preview` отделён от `result`, поэтому незавершённый план никогда не выдаётся за итог.
- **AI с контролем галлюцинаций:** OpenAI Responses API, строгая JSON-схема, `_grounded()` сверяет каждое число ответа с фактами и проверяет покрытие всех выбранных мер; кэш по хэшу; таймаут 16 с, повторный запрос, если ответ не прошёл проверку, и честный fallback с конкретной причиной в `fallbackReason` (например, `OpenAI: NotFoundError — модель '…' недоступна для ключа`) и в логе `akim.ai`; ключ API туда не попадает (`backend/app/ai.py`). Тесты: `test_ai_numerical_guard`, `test_ai_structured_response_path_without_external_call` (путь модели проверяется без сетевого вызова), `test_ai_failure_reason_is_specific_logged_and_secret_free`.
- **Оптимизация без эвристик:** полный перебор 694 395 планов, быстрая формула сверена с основной (`test_fast_search_score_matches_public_simulator_across_plans`), кэш на диске с хэшем данных. При событии перебор идёт в его условиях (показатели после события, бюджет с учётом `budgetDelta`), и Score совпадает с `/api/simulate` для того же события (`test_improve_during_event_uses_event_budget_and_matches_simulate`, `test_event_conditions_match_simulator`). Первый перебор на событие занимает 10–20 с, затем ответ берётся из кэша.
- **Реализация соответствует заявленной логике:** контрольные числа датасета закреплены тестами (`test_dataset_and_baseline`, `test_example_and_order_independence`, `test_optimizer_matches_reference`), включая строгий порог `< 40` и ограничение 0–100 (`test_strict_critical_threshold_and_clipping`), область синергий и несовместимостей (`test_synergy_scope_and_same_district_conflicts`).
- **Фронтенд:** React 19 + TypeScript (strict typecheck в `test.sh`), адаптер API с режимами `http` / `mock`, защита от запоздавших ответов, AI-анализ помечается устаревшим при смене плана.
- **Agentic AI:** `POST /api/agent` (`backend/app/agent.py`) — агент на OpenAI Responses API с function calling. Он сам вызывает инструменты `simulate_plan` и `find_improvements` (при событии оба считают в его условиях), проверяет гипотезы и возвращает рекомендованный план. Сервер пересчитывает рекомендацию и сверяет числа в тексте с результатами инструментов; неподтверждённые числа помечаются (`grounded: false` + `groundingNote`). Ход работы агента виден в интерфейсе по шагам. Тесты `test_agent_tool_loop_with_scripted_model`, `test_agent_find_improvements_works_during_event`, `test_agent_failure_reason_is_specific_logged_and_secret_free` проверяют цикл, событие и ошибки без внешних вызовов.

## 3. README и воспроизводимость (25)

- `README.md`: назначение, быстрый старт из трёх шагов, режим разработки, основной сценарий, схема устройства, формула, соответствие требованиям, проверка, структура, ограничения, источники.
- Скрипты `scripts/setup.sh`, `start.sh`, `dev.sh`, `test.sh` работают из любой папки на macOS и Linux, проверяют версии Python и Node и понятно объясняют ошибки.
- Одна команда запуска: UI и API на http://127.0.0.1:8000. Ключ OpenAI не обязателен.
- Проверка: `./scripts/test.sh` плюс `curl`-примеры в README с ожидаемым выводом (`True 95 52.56 56.54`, `694395 99.9 57.24 57.21`, при секвестре `400145 56.54 99.9 57.19 88`).
- Раздел «Если что-то не работает» в README: где смотреть причину fallback AI, почему первый перебор при событии идёт 10–20 с, что делать с занятым портом.
- Сценарий демо с точными кликами и числами: `docs/demo-scenario.md`; контракт API: `docs/api-contract.md`.
- Зависимости зафиксированы: `backend/requirements.txt` (диапазоны версий), `frontend/package-lock.json` (`npm ci`).

## 4. Ценность и применимость (15)

- Инструмент учит принимать решения при ограниченном бюджете: видно, что концентрация на худшем районе (Нура) даёт больше, чем равномерное распределение; «Слабый план» (всё в Байконуре) опускает Score ниже базы (52.04).
- Формула Score учитывает справедливость: 30 % веса у худшего района и штраф за каждый критический показатель. Поэтому выгоднее «подтянуть отстающих», чем улучшать благополучные районы.
- Прозрачность: каждое число объяснимо через факты, презентацию можно отдать как обоснование решения.
- Применения: обучение госслужащих и студентов урбанистики, командные игры, публичные обсуждения бюджета с жителями, демонстрация компромиссов между направлениями.

## 5. Потенциал развития и оригинальность (10)

- Реальные контуры районов Астаны (OpenStreetMap) и конвейер `scripts/build_geometry.py`: переход на реальные данные и большее число районов не требует переделки карты.
- Точный ответ «насколько хорош план» (процентиль среди всех допустимых) и глобальный оптимум — редкость для симуляторов такого рода.
- AI, которому можно доверять: заявленное свойство «не выдумывает числа» проверяется кодом, а не только промптом.
- Путь развития: открытые данные акимата, несколько агентов-советников по направлениям, общий облачный лидерборд, история сценариев. При росте каталога (примерно от 10⁷ планов) — branch-and-bound или beam search с той же `fast_score` вместо точного перебора.
