# Фронтенд «Аким на 5 часов» (`product.v2/frontend`)

Один экран симулятора: каталог мер, карта районов Астаны, пять решений акима, Score, AI-анализ, улучшение плана, события, лидерборд и экспорт презентации. Стек: React 19, TypeScript, Vite, Tailwind 4.

**Весь продукт одной командой** (UI + API на http://127.0.0.1:8000) запускается из корня продукта: `./scripts/setup.sh`, затем `./scripts/start.sh`. Режим разработки с hot reload для сервера и интерфейса: `./scripts/dev.sh`. Подробности в [корневом README](../README.md), контракт API в [`docs/api-contract.md`](../docs/api-contract.md).

## Только интерфейс

```bash
cd frontend
npm ci
npm run dev          # http://localhost:5173; /api проксируется на http://127.0.0.1:8000 (vite.config.ts)
npm run typecheck    # tsc --noEmit
npm run build        # typecheck + сборка в dist/ (её отдаёт FastAPI на том же порту)
```

## Режимы API (`VITE_API_MODE`)

| Значение | Поведение |
| --- | --- |
| не задано или `auto` | **По умолчанию.** При старте один раз вызывается `GET /api/health` (таймаут 2,5 с). Сервер ответил — все запросы идут на него, чип в шапке «сервер». Не ответил — расчёт в браузере, чип «демо-режим». |
| `http` | Всегда сервер, без перехода на mock: ошибки сервера показываются в интерфейсе. В этом режиме собирают и запускают UI `start.sh`, `dev.sh` и `test.sh`. |
| `mock` | Всё считается в браузере (`src/api/mock/engine.ts`, порт формулы сервера). Процентиль приблизительный (выборка планов), оптимум показывается только без события, AI-пояснение собирается шаблоном и помечено «без AI», AI-агент недоступен. |

Переменные читаются из окружения или `frontend/.env`. Шаблон `.env.example` задаёт `VITE_API_MODE=http`: если скопировать его в `.env`, режим `auto` отключится. `VITE_API_BASE` меняет адрес API (по умолчанию относительный `/api`).

## Как устроено

```text
src/
  App.tsx                 компоновка экрана, запросы improve / explain / presentation
  api/index.ts            выбор реализации (auto → проверка /api/health) и единый объект api
  api/http.ts             fetch к серверу, разбор ошибок FastAPI (422 с detail.errors и т. п.)
  api/adapter.ts          приведение ответов сервера к типам интерфейса, чистые функции
  api/mock/               расчёт в браузере для режима mock
  api/types.ts            типы интерфейса Api и ответов
  data/dataset.ts         каталог из датасета (районы, меры, правила, сценарии, события) для mock и подсказок
  data/astanaGeometry.ts  SVG-контуры районов (из astana_districts.geojson, scripts/build_geometry.py)
  state/                  usePlan (план из пяти решений), useSimulation (пересчёт, отбрасывание запоздавших ответов)
  lib/                    доступность мер, шкалы цветов, форматирование, тексты
  components/             шапка, каталог, карта, портфель, результат, AI-панель, агент, улучшение, событие, лидерборд
```

Итоговые числа (стоимость, допустимость, Score, процентиль) приходят от сервера. Интерфейс сам использует только данные каталога для подсказок: цену, лимит направления, несовместимости. События в `dataset.ts` совпадают с `backend/app/events.py`. Источник истины — сервер: в режиме `http` каталог и события берутся из `GET /api/catalog`.

## Какие запросы делает интерфейс

Тело всех запросов с планом: `{"decisions": [{"measureId": "M7", "districtId": "nura"}, …], "eventId": null}`.

- `GET /api/catalog` — каталог; тексты, которых нет на сервере (короткие названия, «в Нуре», смысл показателей, готовые сценарии), берутся из `dataset.ts`.
- `POST /api/simulate` — на каждое изменение плана. Интерфейс показывает `result`, а для неполного или недопустимого плана `preview` (what-if расчёт).
- `POST /api/improve` — для допустимого плана: процентиль среди всех допустимых планов, глобальный оптимум, лучшая замена одной меры. Сервер поддерживает и `eventId`: тогда перебор идёт в условиях события, и первый запрос на событие занимает 10–20 с.
- `POST /api/explain` — AI-анализ `{status: "ai" | "fallback_no_ai", summary, strengths, risks, consequences, recommendations, decisions[], model, cached, grounded, fallbackReason}`; `fallbackReason` объясняет, почему ответ собран без модели.
- `POST /api/agent` — AI-агент с инструментами (`goal` необязателен); работает только с сервером и ключом OpenAI.
- `POST /api/events/draw` `{excludeId}` — случайное событие; его `id` уходит как `eventId` в следующие запросы.
- `GET /api/leaderboard`, `POST /api/leaderboard` `{teamName, decisions, eventId}` — сервер пересчитывает Score и не принимает записи во время события (HTTP 422).
- `POST /api/presentation` — тело плана, ответ `{filename: "akim-plan.md", markdown, explanationStatus: "ai" | "fallback_no_ai"}`. Для недопустимого плана HTTP 422. Интерфейс сохраняет `markdown` как файл `akim-plan.md`.

## Принципы интерфейса

- Один экран: город реагирует на каждое решение, результат пересчитывается сразу.
- Дельты важнее абсолютных чисел: разброс Score между планами узкий.
- Недоступная мера объясняет причину: бюджет, лимит направления, несовместимость.
- При выборе района видно текущее значение нужного показателя, худший район помечен «нужнее всего».
- Карта — реальные границы районов (OpenStreetMap, ODbL); критическое состояние помечается иконкой, а не только цветом.
