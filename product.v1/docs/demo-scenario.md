# Демо для жюри: 3 минуты

Подготовка (до выхода на сцену):

```bash
./scripts/setup.sh           # один раз
./scripts/start.sh           # прогревает кэш перебора, печатает URL
```

Откройте http://127.0.0.1:8000. В шапке у названия должен быть чип «сервер», а не «демо-режим». Если есть ключ OpenAI, заранее один раз нажмите «AI-анализ» на примере организаторов: ответ закэшируется, и на сцене он появится мгновенно. Перед показом очистите план: «Сценарии…» → «Очистить план».

Все числа ниже — для правил `RULESET=dataset` и получены тем же движком, что закреплён в `backend/tests/test_core.py`. В интерфейсе они выводятся в русском формате (56,54).

## 1:00–1:40 — AI-анализ

Клик **«AI-анализ»** в шапке.

**Показать:** сводку, блоки «Сильные стороны», «Риски», «Последствия», «По каждому решению», «Рекомендации». Чип справа: `gpt-… · числа сверены` (с ключом) или `без AI · из фактов расчёта` (без ключа).

**Сказать:** «Модель не считает. Она получает только факты расчёта, а сервер проверяет, что каждое число в её ответе есть в этих фактах. Если нет — показываем честный шаблон с пометкой „без AI“, а не выдуманные цифры».

Верните пример: «Сценарии…» → «Пример организаторов» (56.54).

## 2:10–2:40 — Неожиданное событие и контроль бюджета

Карточка «Неожиданное событие» → **«Разыграть»**. Событие случайное; нажимайте «Другое событие», пока не выпадет **«Секвестр бюджета»** (всего 4 события).

| Событие | База | Пример организаторов |
| --- | --- | --- |
| Секвестр бюджета (лимит 90) | 52.56 | **недопустим**: 95 > 90, в шапке «превышен на 5», ошибка «Бюджет превышен» |
| Смог (E2 −6 в Сарыарке) | 51.47, критических 3 | 56.45, критических 0 |
| Аварийная зима (C1 −8 в Алматы) | 52.42 | 56.41 |
| Рост населения Нуры (S1 −5 в Нуре) | 52.33 | 56.32 |

При секвестре: в «Пять решений акима» уберите M5 (крестик), затем в каталоге «Парк / сквер» (M4) → **Сарыарка**. Стоимость 85 из 90, план снова допустим, Score **56.54**.

**Сказать:** «Превысить бюджет невозможно ни в интерфейсе, ни через API: сервер отклоняет такой план с кодом BUDGET_EXCEEDED».

Затем «Сбросить» событие.

## 2:40–3:00 — Команды и презентация

- **«Команды»** → ввести название команды → «Записать». Строка в таблице со Score **56.54**. Сервер пересчитывает Score сам и не принимает записи во время события, поэтому все команды сравниваются в равных условиях.
- В панели AI-анализа → **«Скачать презентацию»** → файл `akim-plan.md`: итог, решения, районы до/после, факты, выводы AI.

**Финал:** «Детерминированное ядро, полный перебор и AI, который объясняет, но не выдумывает. Всё запускается двумя командами, проверяется `./scripts/test.sh`».

## Запасной вариант без интерфейса

```bash
PLAN='{"decisions":[{"measureId":"M7","districtId":"nura"},{"measureId":"M8","districtId":"nura"},{"measureId":"M10","districtId":"nura"},{"measureId":"M12","districtId":null},{"measureId":"M5","districtId":"saryarka"}]}'
curl -s -X POST http://127.0.0.1:8000/api/simulate -H 'Content-Type: application/json' -d "$PLAN" | python3 -m json.tool | head -40
```

Дополнительный сюжет: «Сценарии…» → «Слабый план» (всё в Байконуре) даёт Score **52.04**, ниже базы (−0.52). «Улучшить план» предлагает заменить «Безопасные переходы» в Алматы на ЛРТ в Нуре (**53.74**). Так видно, что рекомендации адресуют худший район.
